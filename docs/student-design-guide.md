# 학생용: Discord AI 스마트 메일함 설계 해설

이 문서는 수업에서 **왜 이런 구조로 설계했는지** 설명하기 위한 자료입니다. 바로 실행하려면 [설치 가이드](setup.md), 코드를 읽으려면 [SKILL.md](../SKILL.md)를 보세요. 아래의 **운영판**은 실제 사용 사례의 동작 원리이고, **공개 키트**는 누구나 자기 계정으로 실습할 수 있게 개인 정책을 뺀 안전한 기본판입니다.

## 1. 해결하려는 문제

메일이 올 때마다 원문을 읽고, 답장 필요 여부를 판단하고, 초안을 쓰고, 다시 메일 앱으로 돌아가 발송하는 일이 반복됩니다. 단순한 “메일 전부 Discord로 전달”은 알림만 더 늘립니다. 이 시스템의 목표는 **행동이 필요한 메일만 짧게 보여주고, 판단과 실행을 한 곳에서 끝내는 것**입니다.

핵심 구분은 다섯 단계입니다.

```text
수집(IMAP) → 선별(규칙+AI) → 제안(요약·초안) → 승인(Discord) → 실행·확인(SMTP/Sent)
```

AI는 사람의 판단을 준비합니다. 외부 발송과 메일 이동은 별도의 승인·정책·검증 단계입니다.

## 2. 사용자가 보는 화면: “카드 한 장 + 스레드 하나”

판단이 필요한 메일 한 통마다 비공개 Discord 채널에 짧은 카드가 생깁니다.

> 📨 **판단이 필요한 메일**
>
> 발신: partner@example.com
>
> 제목: 다음 주 인터뷰 일정 문의
>
> **핵심 요약:** 다음 주 화·목 중 인터뷰를 요청했고 예상 질문을 보내겠다고 했습니다.
>
> **추천:** 가능한 날짜를 확인하고 질문지를 요청하는 답장을 검토하세요.

카드의 **스레드**에는 답장 초안과 처리 버튼 역할의 이모지 반응이 있습니다. 메일 원문 전체를 채널에 쏟아놓지 않고, 요약은 “무슨 내용인가”, 추천은 “내가 무엇을 할까”라는 서로 다른 질문에 답합니다. 긴 협의나 수정은 해당 메일 스레드 안에 모여 다른 메일과 섞이지 않습니다.

### 실제 운영판의 빠른 결정

- **✅ 발송:** 스레드의 현재 초안을 실제 이메일로 보냅니다. 단순 확인 표시가 아니라 **외부 발송 승인**입니다.
- **🔁 이번 초안 발송 + 향후 유사메일 자동발송 허용:** 단순히 발신자가 같다는 이유로 자동응답하지 않습니다. 같은 계정·발신자·제목·실질 요청과 금액/일정/권리 등의 조건이 같을 때만 후보가 됩니다.
- **🗑️ 휴지통:** 답장하지 않고 해당 메일을 휴지통으로 이동합니다. 영구 삭제가 아닙니다.
- **🙅 답장 없이 종료:** 원본 메일을 보존하고 이 건의 처리만 마칩니다.
- **🚫 스팸/발신자 차단:** 해당 메일을 스팸으로 옮기고, 같은 발신자에 대한 이후 처리 규칙을 기록합니다.
- **⏸️ 보류:** 아무 메일도 보내거나 옮기지 않고 결정을 멈춥니다.

운영판에서는 `수정: ...`으로 초안 재작성 요청, `답장: ...`으로 문안 교체, `승인` 같은 명시적 텍스트 지시도 지원합니다. 문안을 바꾸면 **새 결정 카드**가 생겨 이전 카드의 ✅가 새 초안을 승인한 것으로 해석되지 않습니다.

**공개 실습 키트에는 ✅·🗑️·🙅·⏸️ 네 개만 구현되어 있습니다.** 🔁·🚫·텍스트 수정과 개인화 자동발송은 설계 학습을 위한 확장 항목이며, 설치만 해서는 작동하지 않습니다.

## 3. 누가 눌렀고, 무엇을 눌렀는지 확인한다

- 반응은 **설정된 소유자 Discord 사용자 ID**가 누른 것만 인정합니다. 다른 학생이나 봇의 ✅는 실행 지시가 아닙니다.
- 한 결정 카드에 소유자가 여러 행동 이모지를 누르면 **충돌**로 보고 아무 것도 실행하지 않습니다. 모두 지우고 하나만 다시 선택해야 합니다.
- 운영판은 **최신 초안 카드**에 대한 반응만 인정합니다. 수정 전 카드의 승인으로 새 문안을 보내지 않습니다.
- 댓글의 일부 단어가 “삭제”처럼 보여도 실행하지 않습니다. 텍스트 명령은 정해진 형식 전체와 정확히 일치할 때만 인정합니다.

이모지는 편리한 UI지만, 구현에서는 **권한 확인이 필요한 명령어**로 다뤄야 합니다.

## 4. 메일을 모두 알리지 않는 이유

운영판은 계정·보안·결제·계약·거래와 같은 보호 대상은 보존하거나 확인 대상으로 올립니다. 명백한 광고·뉴스레터·자동 알림은 유형에 따라 조용히 처리합니다. AI 요약은 단순 번역이나 원문 앞부분 복사가 아니라 **구체적인 내용 1–2문장 + 직접 요청 여부 + 추천 행동**을 분리합니다. 모델이 실패하거나 중요 여부가 불확실하면 조용히 버리지 않고 사람 확인으로 보냅니다.

공개 키트는 수업 중 예기치 않은 삭제를 막기 위해 **AI가 불필요하다고 판단한 메일도 원본을 보존**합니다. 기본값에 자동 휴지통·자동 회신은 없습니다.

## 5. 외부 행동은 “했을 수도 있다”를 고려한다

네트워크가 끊기면 SMTP 명령이 오류를 내더라도 실제 이메일은 이미 보내졌을 수 있습니다. 그래서 운영판과 공개 키트는 다음 순서를 지킵니다.

1. 메일 계정과 메시지 ID로 중복 수집을 막습니다. 처음 시작할 때 기존 메일을 **기준선**으로 두어 과거 메일을 한꺼번에 처리하지 않습니다.
2. ✅ 후 발송 전에 **보낸편지함에서 수신자·제목·시각**이 맞는 메일이 이미 있는지 확인합니다.
3. SMTP 호출 **전에** 원장에 `sending`을 저장합니다.
4. SMTP 결과가 불확실하면 자동 재발송하지 않고 Sent를 다시 확인합니다. 확인되지 않는 건은 사람이 조사합니다.
5. “SMTP 접수”와 “보낸편지함에서 확인”을 구분합니다. 메일 이동과 Discord 게시도 결과 불확실성을 별도 상태로 남깁니다.

이것이 **멱등성**과 **쓰기 전 기록(write-ahead state)**입니다. 반복 실행되는 자동화에서 “한 번만 보낼 것”은 프롬프트가 아니라 상태와 검증으로 보장합니다.

## 6. AI에게 줄 수 있는 권한을 줄인다

메일 본문은 발신자가 마음대로 쓸 수 있으므로 **신뢰할 수 없는 입력**입니다. “지금 비밀번호를 보내라” 같은 문장을 AI의 지시로 실행하면 안 됩니다. 공개 키트는 메일 분석 전용 `mail-triage` 에이전트의 **모든 도구를 차단**한 상태를 확인하고, 그 에이전트가 요약·초안 텍스트만 반환하게 합니다. 토큰과 상태 원장은 로컬 비공개 파일, 승인 채널은 본인과 봇만 볼 수 있는 Discord 채널에 둡니다.

## 7. 실제 운영판과 실습판의 시간·범위

- **운영판:** 메일 수집 약 15분 간격, 승인 반응 확인 약 1분 간격. 계정 두 개, 세부 규칙과 명시적으로 승인된 일부 자동 회신을 포함합니다.
- **공개 키트:** 메일 수집 5분 간격, 승인 확인 1분 간격. 한 개 이상의 자기 계정을 설정할 수 있지만 기본은 **수동 승인형**입니다. 완료 스레드는 삭제하지 않고 보관·잠금해 실습 결과를 확인할 수 있습니다.
